# Task 1.5.5 – Alerts list, mark all read, tab badge; alert on/off in Device settings

## Goal

The Alerts tab lists every alert the phone raised for the logged-in user, newest first, with "Mark all read". The tab shows a badge with the unread count. Each device's alert limits can be turned on or off in Device settings.

## Requirements covered

- 7.2 Show alerts in an Alerts list; mark all as read.
- 7.3 Sample alerts: "Heart rate above 110 bpm", "CO₂ above 1,000 ppm", "Battery low (12%)", "Missed 3 heartbeats – device offline".
- 8.4 Turn each alert limit on or off (Device settings, since 1.2.9).
- Mockup screen 34 (Alerts) and its tab bar badge; screen 38 (Device settings, Alerts section). The filter chips come from mockup v2.1 (decision 2026-11-20).

## Scope

**In scope**

- **Alerts list** (`AlertsScreen` at `/alerts`, replacing the placeholder):
  - The title "Alerts" and "Mark all read" (accent; disabled when nothing is unread).
  - One card per stored alert, newest first: a round icon (the reading's icon from the profile; a battery for low battery; a pulse for Offline), the title, "device · time", a source chip ("THRESHOLD" for above/below, "DEVICE HEALTH" for battery and Offline) and a dot while unread.
  - Colours: unread battery and Offline alerts use danger, unread above/below use warn, read ones are muted. "Unread" is spoken, so colour is never the only signal.
  - Titles are the same words as the notification (1.5.4's `alertTitle`).
  - Time: "Just now", "10 min ago" (under 1 h), "Today, 07:10", "Yesterday, 18:40", "Fri 23 Oct, 13:05"; 24-hour, as elsewhere in the app; updated every minute while open.
  - Empty: a dashed card "No alerts / Alerts from your devices will show here."; a failed load says so.
  - Alerts of a device no longer in the user's list are not shown.
- **Filters** (mockup v2.1): a sideways-scrolling row of chips under the title: All · Readings · Device events · Episodes · Channels · Device health. The picked one is filled with the primary colour and announced as selected; it stays while the user visits other tabs. Above / below are Readings; battery and Offline are Device health. Device events, Episodes and Channels are shown as in the mockup but stay empty ("No alerts of this type yet.") until those alert types exist.
- **Mark all read**: marks all of the user's alerts read, whatever the filter, and shows "All alerts marked as read". Only this button marks alerts read; opening the tab does not. A failure says so.
- **Deleting** (not in the mockup; decision 2026-11-20): swipe a card left to delete it (the red Delete panel of the device cards); "Alert deleted" offers Undo. Screen readers get a "Delete alert" action. "Clear all" next to "Mark all read" asks "Clear all alerts?", then deletes all of the user's alerts, whatever the filter; it is off with no alerts. Failures say so.
- **Tab badge**: the unread count on the Alerts tab, "99+" above 99, hidden at 0 and when `features.alerts` is false. A screen reader hears "8 unread" with the tab.
- **Device settings**: the Alerts section (on/off per limit, since 1.2.9) is hidden when `features.alerts` is false. A limit turned on or off applies to the engine at once.

**Out of scope**

- The mockup's other alert types (device events, channel groups, ECG episodes, data gaps): the engine does not raise them yet.
- Tapping an alert (the mockup gives it no action).
- Changing alert limit values (requirement 8.4 is on/off only).

## Acceptance criteria

- [x] Every stored alert of the user is listed newest first with the mockup's title, "device · time" and source chip; unread ones have a dot and are spoken as unread.
- [x] No alerts shows the empty card; a failed load says so.
- [x] The six filters show; each shows only its alerts, an empty one says "No alerts of this type yet.", and the picked one is announced as selected.
- [x] Mark all read marks them read and says so; it is disabled when nothing is unread; a failure says so.
- [x] Swiping a card left deletes it with Undo (also a screen reader action); Clear all asks, then deletes them all; failures say so.
- [x] The Alerts tab shows the unread count (1–99, then "99+"), none at 0 or with alerts off.
- [x] Device settings hides the Alerts section with alerts off; a switch saves on/off and applies at once.
- [x] Unit and widget tests (mocktail, table-driven time labels, sources and badge counts), including dark mode and a small phone at double text size; `flutter analyze` and `flutter test` are clean.
- [ ] Checked on a phone (a dummy device over its limit, Mark all read, the badge).
