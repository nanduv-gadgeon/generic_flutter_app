# Task 1.3.6 – Offline banner and Reconnect, device action button, Sync now

## Goal

When the connected device stops being heard from, its dashboard says so in a banner with the last heartbeat time and a **Reconnect** button, and the home card, the status strip and the Connected count say the same thing at the same moment. Under the readings, the dashboard has the profile's device action button (e.g. *Identify sensor*), and *Sync now* fetches the data the device stored (see the 2026-11-13 decision).

## Requirements covered

- 5.5 When the device is offline, show a banner with the last heartbeat time and a *Reconnect* button.
- 5.6 Buttons: **Sync now** (*Phase 2*) and an optional device action (e.g. *Find band* makes it vibrate, *Identify* blinks the sensor LED).
- 12.5 Missed heartbeats mark the device **Offline** and show the offline banner; when heartbeats return it shows **Online** again. (The "Device offline" alert is task 1.5.3.)
- 3.2 The home card's connection: Bluetooth / Wi‑Fi / Offline.
- Accessibility: colour is never the only signal; every button and spinner has a Semantics label.

Test cases: TC-DSH-010 to TC-DSH-014.

## Scope

**In scope**

- **One link state for every screen.** `linkStateOf(status, online, onDemand)` (domain, pure) gives `connected`, `connecting`, `reconnecting`, `offline` or `onDemand`:
  - `offline` when the heartbeat says missed (`!online`) or the device cannot be reached (`waiting`);
  - `onDemand` profiles (they connect only to send a reading) are never offline on their dashboard;
  - `syncing`, `starting` and `streaming` are `connected`.
- **Home card chip:** green *BLE · Connected*; amber *BLE · Connecting…* / *BLE · Reconnecting…*; red *Offline*. Only green counts in the Connected total.
- **Status strip Link cell:** the same state and colours.
- **Background retries stay Offline.** The device-level retry loop (every 60 s when the device cannot be reached) no longer reports *Connecting…* on its later attempts, so the chip does not flash; the first attempt and a user's Reconnect still do.
- **Offline banner** (mockup line 440), under the status strip on the Live tab:
  - shown exactly when the link state is `offline`, never for `onDemand` profiles;
  - "Offline · last heartbeat {time ago}. Showing last readings.", or "Offline · no data from the device yet. Showing last readings."; the readings below keep their last values;
  - **Reconnect** inside the banner: the button shows a spinner and the banner stays while it tries (TC-DSH-011); on success the banner goes (TC-DSH-010); on failure it shows "Could not reconnect. Check the device is on and nearby." and the button can be used again;
  - while the banner shows, the Offline status line under it is not shown, so the time is not said twice;
  - a live region, so screen readers hear it appear.
- **Bottom action row** (mockup line 685), the last item on the Live tab:
  - **Sync now** (changed 2026-11-13): a live fetch from the connected device, nothing to do with the cloud, in both phases. Like the device action it comes from the config, `dashboard.syncNow { label, command | steps, done }`, and is sent the same way (disabled unless connected; the fetched entries are stored by the normal log pipeline). VitaCare: the IEF patch sends `request_logs`; the PPG sensor has none (no documented stored data). Replaces the original "hidden in Phase 1" (TC-DSH-012);
  - **device action** from the profile's new `dashboard.action { label, command? | steps?, done? }`: one profile `command`, or `steps` (each a command, its value byte and a pause after it) sent in order; it shows `done` on success, or an error message (TC-DSH-013, TC-DSH-014). With neither it is a placeholder that says the action is not available yet. While an action runs the AGC waits and worked-out readings are held back; afterwards any LED the AGC drives is set back to the AGC's level;
  - the action is **disabled unless the device is connected** (TC-DSH-014) and shows a spinner while it runs;
  - one button alone takes the full width; with none the row is hidden.
- VitaCare: the PPG + motion sensor's action is **Identify sensor**: its red LED goes to full (32) and off (0) three times, 300 ms apart, then back to the AGC's level ("The sensor light flashed."). The sensor has no vibration, buzzer or identify command (protocol doc and the vendor app); its LEDs are the only physical response the app can drive. Calibrate (`0x04`) was not used: it only recalibrates internally (done at every boot anyway) and nothing visible happens.

**Out of scope**

- The PPG no-data stall (reconnect cool-down and the no-data check): its own commits on this branch, after this part.
- The "Device offline" alert and notification (1.5.3, 1.5.4).
- Real *Find band* / *Identify* commands: the VitaCare band and environment sensor have no protocol yet; the config can name a command once they do.
- The home card for on-demand devices (unchanged).
