# Task 1.4.4 – History screen (step 1: device picker, tabs, day picker)

## Goal

The History tab shows the user's devices and the last days kept on the phone. Each day is marked Complete, Partial or No data, so the user can pick a device and a day. The day's details and the 7-day summary are later steps of this task.

## Requirements covered

- 6.1 History is read from the local database for the last 7 days, in both phases.
- 6.2 Pick a device (picking a reading comes with the day details and the summary).
- 6.3 A day-by-day strip marks each day *Complete*, *Partial* or *No data*.
- Accessibility: colour is never the only signal; every button has a Semantics label; text scales.

Test cases: TC-1.4-002, TC-1.4-003 (device part), TC-1.4-004, TC-1.4-009, TC-1.4-010.

Reference: mockup v2.1 (`device-monitor-mockup-v2.1.html`, History), screens 22 and 23.

## Scope

**In scope**

- **History tab** replaces its placeholder:
  - "History" and "Last 7 days · 20–26 Oct" under it;
  - with no devices, "Add a device to see its history here." (TC-1.4-009).
- **Device picker.** One chip per device, in the home order, scrolling sideways. The picked one is filled. The first device is picked until the user picks another, or when the picked one is removed.
- **By day / 7-day summary** tabs. 7-day summary is an empty page for now. The tab says the config's number of days ("5-day summary").
- **Day picker.** It is worked out from the phone's clock and the config, with no fixed dates:
  - the last `history.daysOnPhone` local calendar days (7 for VitaCare), oldest first, today last ("Today");
  - weekday and date through `intl`, in the phone's language. The header range works across a month ("28 Oct – 3 Nov");
  - at local midnight the strip moves on. If today was picked, the new today is picked; a picked day that leaves the strip falls back to the oldest day;
  - days are local midnight to midnight, so 23 or 25 hours on a clock change.
- **Day status** (pure, `lib/domain/history/history_days.dart`):
  - a day's hours (0 = the first hour after midnight) have data when any reading was stored in them;
  - the hours that count are all of them for a past day. For today, they are the hours begun so far;
  - every hour counted has data: Complete. Some: Partial. None: No data;
  - a device added an hour ago shows today Partial and the days before No data (TC-1.4-010).
- **Legend** Complete / Partial / No data under the strip. Each tile's screen reader label says its status in words ("Thursday, October 22, No data"), or "checking data" while it loads.
- **`SegmentTabs`**: the grey two-tab switch, now shared by History and the device page's Live / History.
- **History on a device's dashboard.** Tapping History under the status strip opens the app's History tab with that device picked, By day, today. The placeholder text it showed is gone. The History controller is kept alive for this. A device id that is no longer the user's falls back to their first device.

**Out of scope**

- Day details: status banner, min / average / max, the reading cards (next steps).
- Charts: the 24-hour charts and the 7-day summary chart (not built in this task step).
- 7-day summary content; Export; the History tab inside a device's page.
- Device-specific history (therapy events, thermometer list, hub heat map, the "activity" day rule).
- **1.4.3** (Dev 1): the `daily_summary` table, 1-minute averages, clean-up. Nothing here depends on it (see below).

## Independent of 1.4.3

This work will be rebased onto 1.4.3, so it uses none of it:

- Day status comes from a new interface, `HistoryRepository.dataSlots`. It gives the 15-minute slots that have readings. Every time zone is a whole number of quarter hours from UTC, so a slot never spans two local hours.
- `LocalHistoryRepository` answers with one read-only query on the existing `readings` table (`TODO(1.4.3)`: read the daily summary instead). There is no schema change.
- Not touched: `tables.dart`, `readings_dao.dart`, `reading_repository.dart`, the clean-up job, `services.dart` (the provider is in its own `core/di/history.dart`).
- Statuses are worked out again once a minute. Until 1.4.3 they scan the device's readings of the last 7 days.
