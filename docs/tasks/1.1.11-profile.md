# Task 1.1.11 – Profile and Edit profile

## Goal

The Profile tab shows who is logged in, with an Edit profile screen. It also has the Notifications and Face ID switches, the customer's privacy and terms links, the app version and Log out. It replaces the temporary Profile placeholder from 1.1.10.

## Requirements covered

- 9.1 Photo or initials, name and email, with an **Edit** button.
- 9.2 Edit profile: change the photo, full name and mobile number, then *Save changes*. **The email is shown greyed out and can't be edited**, because it's the login. This was decided during review and departs from 9.2, which lists email as editable.
- 9.3 Notifications on/off, stored per user.
- 9.4 Auto sync is Phase 2 only. It's **hidden while `isCloud` is false**, through `autoSyncAvailableProvider` in `core/di`. With the cloud on, a placeholder row shows "Auto sync / Not set up yet / Off ›", and tapping it says "Auto sync comes with cloud sync." The `// TODO(phase2)` covers the real schedule and the upload times.
- 9.5 Privacy policy and Terms of use. Each opens the link from the config file's new `links` block in an **in-app web view**, shown in a tall sheet over Profile with a close button (the requirements list privacy and terms links as config text).
- 9.6 App version.
- 9.7 Log out, which asks for confirmation first using `confirmLogout` from 1.1.9.
- A Face ID / fingerprint login switch. The 1.1.6 brief left turning it off to this task, and the biometric offer dialog says "You can turn this off later in your profile". It isn't in the mockup.

## Scope

**In scope**

- `ProfileScreen` from `docs/screens/22_profile.png`, and `EditProfileScreen` from `23_edit_profile.png` (mockup lines 665–734).
- `AuthService.updateProfile` saves the name, mobile and photo. The local version keeps the photo file. The cloud version is a hook (PUT /me).
- Database schema v2: an `app_settings` table, one row per user, for the Notifications switch, plus its migration and test.
- The photo comes from the camera or library through `image_picker`, scaled to 512 px. It's copied into the app's private folder.
- The config `links` block (https only, checked by the schema). VitaCare uses `https://example.com/...` placeholders.
- `WebPageView` (webview_flutter): https only, also for links tapped inside the page. JavaScript is off. It shows a spinner while loading and an error message if the page fails.

**Out of scope**

- The customer's real privacy and terms URLs. The example.com values are placeholders.
- The Notifications switch actually silencing alerts. The alerts module will read `app_settings`.
- Asking for the phone's notification permission (alerts module).
- Auto sync (9.4) and uploading the photo to the cloud (Phase 2).

## Exception to the "no network calls in Phase 1" rule

CLAUDE.md says: "With `isCloud: false` the app makes zero network calls." The in-app web view for Privacy policy and Terms of use breaks this, by choice (decided during review of this task):
- The app now loads those two pages itself, over https, and only when the user taps the row. Nothing else uses the network.
- Android's main manifest now asks for the `INTERNET` permission. Until now only debug builds had it.
- **The team needs to agree this exception** (CLAUDE.md, decisions.md and the security review). The alternative that keeps the rule is bundling the pages as local files.

## Details

- The mobile number is stored as `+91 9876543210`. When editing, it's split back into the country code and the number:
  - The longest matching code wins, so `+1 876` gives Jamaica.
  - A code shared by several countries (`+44`, `+1`) picks the phone's region when its code matches.
- Photo: picking only previews it, and nothing is saved until *Save changes*. A replaced or removed photo's file is deleted after the save. If the file is missing, the initials show instead.
- Profile photos are personal data. They're kept in the app's private folder (not visible in the Files app), but **not encrypted** like the database. This is flagged for the pre-release security review.
- The Face ID switch shows only when `features.faceIdLogin` is on and the phone has biometrics. Turning it off removes the biometric button from login.
