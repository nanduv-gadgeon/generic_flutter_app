# Task 1.1.5 – Local database (Drift + SQLCipher): users, session, devices

## Goal

An encrypted local database that later tasks build on. Login and registration (1.1.6, 1.1.8) and Add device (1.2.7) store their data here.

## Requirements covered

- 10.1 Readings, devices and the local user account are kept in an encrypted local database (this task: users, session and devices).
- 2.1–2.4 Account data needed by register, login, forgot password and log out (storage only; hashing is 1.1.6).
- Security: local accounts stored as a salted hash with failed-login lock-out; the database is encrypted with SQLCipher and its key is kept in Keychain / Keystore.
- Privacy: deleting an account deletes its session and devices.

## Scope

**In scope**

- Drift tables `users`, `sessions` and `devices`, with constraints and indexes.
- `UsersDao`, `SessionDao` and `DevicesDao`.
- The database key: 32 random bytes, kept in flutter_secure_storage.
- Opening the database with SQLCipher; it refuses to open unencrypted.
- A Riverpod provider. The splash screen opens the database at start-up.
- A migration scaffold (`drift_schemas/`, generated schema tests).
- Android auto-backup off.

**Out of scope**

- Password hashing and login logic (1.1.6).
- Readings, heartbeats, alerts, upload state and settings tables (later modules).
- Domain repository interfaces (added with the services in 1.1.6 and 1.2.7).

## Phase behaviour

| isCloud | Behaviour |
| --- | --- |
| false (Phase 1) | Database used for accounts, session and devices. No network calls. |
| true (Phase 2) | Same database. `devices.deviceKey` is filled from the cloud (1.2.7 hook). Tokens go in flutter_secure_storage, never in the DB. |

## Acceptance criteria

- [ ] The database file is encrypted: it does not start with `SQLite format 3`, and it does not open with a wrong key.
- [ ] If SQLCipher is missing, opening fails; the app never falls back to an unencrypted DB.
- [ ] The key is created once, reused, and never logged. A lost key over an existing DB is an error, not a silent reset.
- [ ] Emails are unique, regardless of letter case.
- [ ] A device address is unique per user; `batteryPercent` is 0–100.
- [ ] Deleting a user cascades to the session and devices.
- [ ] The splash screen shows an error if the database cannot be opened.
- [ ] Unit tests added (mocktail); `flutter analyze` and `flutter test` are clean.
- [ ] The debug APK builds with SQLCipher.
