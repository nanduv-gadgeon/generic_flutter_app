# Task 1.1.6 – Login and Face ID login; password hashing service; session handling

## Goal

A user can log in with email and password, or with Face ID / fingerprint after turning it on. The login is kept until they log out. Dev 2 gets a ready `AuthService` (including `register`) and a hashing service for registration (1.1.8) and forgot password (1.1.9).

## Requirements covered

- 2.2 Log in with email and password; optionally with Face ID / fingerprint after the first login.
- 2.4 Log out ends the session on the phone (service method; the button comes in 1.1.9).
- 2.5 Each account action shows a loading spinner with no text.
- Security design, "Local accounts": salted Argon2id hash. The lock-out is not built, by decision (see below).

## Scope

**In scope**

- `AuthService`, `PasswordHasher` and `BiometricAuth` interfaces in `lib/domain/services/`.
- `LocalAuthService`, `Argon2idPasswordHasher`, `LocalBiometricAuth` and `BiometricUserStore` in `lib/data/auth/`.
- An empty `CloudAuthService` hook.
- `AuthController` holds the session and restores it during the splash screen.
- A router guard, which redirects between the logged-in and logged-out screens.
- The login screen from the mockup, and the one-time Face ID offer.
- Android and iOS setup for biometrics.

**Out of scope**

- The registration screen (1.1.8).
- Forgot password, and the log out button (1.1.9).
- The landing screen (1.1.10). `/home` is a placeholder with a temporary Log out button.
- Turning Face ID off in Profile (1.1.11).
- The Phase 2 cloud login.

| true (Phase 2) | `CloudAuthService`: methods are `// TODO(phase2)` hooks. `currentUser` returns null, so the app shows login. |

## Decisions (see docs/decisions.md)

- No lock-out after wrong passwords. This departs from the architecture's Security design and must be accepted in the security review.
- The session lasts until log out.
- Face ID is offered once after the first password login. One Face ID user per phone: the latest to turn it on.

## Acceptance criteria

- [x] A wrong email or password shows the same message, and takes about as long either way.
- [x] Passwords are stored only as a salted Argon2id hash, with their settings, and are re-hashed on login when the settings change.
- [x] The session survives a restart. The splash screen goes to home if it exists, otherwise to login.
- [x] The Face ID button shows only when `features.faceIdLogin` is on and a user has turned it on.
- [x] The busy spinner has no text and has the Semantics label "Signing in". Errors show an icon as well as colour.
- [x] Unit and widget tests are added (mocktail). `flutter analyze` and `flutter test` are clean.
- [ ] Manual check on a real phone after 1.1.8: register, log in, turn on Face ID, restart, log out, log in with Face ID.
