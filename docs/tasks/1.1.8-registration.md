# Task 1.1.8 – User registration (local account)

## Goal

A new user can create a local account on the phone and goes straight to the landing screen, logged in.

## Requirements covered

- 2.1 Register with name, email, mobile number and password, and accept the terms. Phase 1: the account is created on the phone, with the password stored only as a secure hash.
- 2.5 The account action shows a loading spinner with no text.
- Config `features.registration`: when it is off, both the link and the route are hidden.

## Scope

**In scope**

- The register screen from `docs/screens/03_register.png`.
- `AuthController.register`: creates the account (the existing `AuthService.register`), then logs it in.
- The shared auth form pieces (`emailPattern`, `AuthSubmitButton`, `AuthErrorMessage`), moved out of the login screen.
- Blocking the `/register` route when registration is off.

**Out of scope**

- Links to the Terms and Privacy Policy (plain text until the config has their URLs).
- The Face ID offer: it comes with the first password login, as before.
- The landing screen itself (1.1.10). `/home` is still the placeholder.
- Phase 2 cloud registration.

## Decisions

- After registering, the user is logged in and goes to the landing screen; the mockup's "Account created" toast is shown.
- Validation: name not blank; valid email; password at least 8 characters; the two passwords must match; the terms must be ticked.
- Mobile number: a country-code button (code and ▾, no flags) next to the number. It opens a bottom sheet with a search box (country name, ISO code or dial code; `filterDialCodes`) and a lazily built list (`ListView.builder`), so only visible rows are built. This replaced Flutter's `DropdownMenu`, which built all ~240 rows at once and was slow on a low-end test phone.
  - The codes are a `const` list in `lib/domain/models/dial_code.dart` (ISO code, country name, dial code), taken from the ITU-T E.164 list. Edit one line to add or fix a code; `test/domain/models/dial_code_test.dart` checks it. **To be reviewed against the official ITU list before release.**
  - Default: the phone's region (e.g. `en_GB` → +44), else India +91.
  - Saved as `<code> <digits>`, e.g. `+91 9876543210`, in the existing `mobile` column (no schema change).

## Mobile number validation

Checked when **Create account** is tapped, by `isValidNationalNumber(number, dialCode)` in `lib/presentation/auth/mobile_number_field.dart`. The number typed (without the code) must pass all three rules, or the field shows "Enter a valid mobile number." and nothing is saved:

1. **Digits, spaces and dashes only, starting with a digit** (`^[0-9][0-9 \-]*$`, after trimming). A `+` is rejected: the code comes from the dropdown.
2. **4–14 digits**, counted after removing spaces and dashes. 14 is the longest national number in any country.
3. **At most 15 digits including the code** (the E.164 limit). `DialCode.digitCount` gives the code's digits (+91 → 2, +1 876 → 4), so India allows up to 13 digits and Jamaica up to 11.

Then `fullMobileNumber(dialCode, number)` builds the stored value: the code, a space and the digits only (`98765-43210` with India → `+91 9876543210`).

| Typed (India +91) | Digits | Result |
| --- | --- | --- |
| `98765 43210` | 10 (+2 = 12) | Valid |
| `000-000-0000` | 10 | Valid |
| `0000` | 4 | Valid (minimum) |
| `000` | 3 | Too short |
| `0000000000000` | 13 (+2 = 15) | Valid (maximum) |
| `00000000000000` | 14 (+2 = 16) | Too long |
| `+91 0000000000` | – | Contains `+` |
| `00000 abcde` | – | Contains letters |

**Not checked (known limits):**

- The exact length for each country (e.g. Indian mobiles are 10 digits); this would need a phone-number library added with `flutter pub add`.
- Whether the number is a mobile or a landline.
- Ownership: no SMS code (Phase 1 makes no network calls).
- Uniqueness: two accounts may share a mobile number; only the email must be unique.

Tests: `isValidNationalNumber`, `fullMobileNumber` and the mobile rows of `rejects …` in `test/presentation/auth/register_screen_test.dart`.
