# Task 1.2.7 – Add device 4-step flow; save with config alert defaults; empty Phase 2 hook

## Goal

The user can add a device of any configured type that can connect: pick the type, pick Bluetooth or Wi‑Fi, find or set up the device, then name it. It is saved on the phone with its type's default alert limits. In Phase 2 an empty hook is where the cloud will register it and send back a device key and suggested alerts.

## Requirements covered

- §4 Add a device, steps 1–4.
- Config file: device types, connection options, default alerts.
- Mockup screens 10 (types), 11 (BLE scan), 12 (registered); mockup HTML for step 2, the Wi‑Fi form and the registering checklist.

## Scope

**In scope**

- Schema v3: `device_alerts` table (per-device alert limits) and `devices.ip_address`.
- `DeviceService.addDevice / rename / isAdded`; `DeviceRegistration` (Phase 1: none; Phase 2: empty hook).
- `AddDeviceController` (Riverpod) and the screen with its steps: types, connection, BLE scan, Wi‑Fi form, device hotspot instructions, registering, done.
- Device key card (Phase 2 only), alert settings card, device name.
- Bluetooth permission request before scanning.
- The scan runs for 20 s, then stops with the found devices still listed and a "Scan again" button.
- "Disconnect" on a scanned device already added: asks, then removes it (and its alerts) from the phone so it can be added again.
- `/device/:id` placeholder, where "Go to dashboard" lands.
- Shared form widgets moved out of the auth folder (`CircleBackButton`, `PrimaryButton`, `ErrorMessage`).

**Out of scope**

- The device dashboard (its own task); live connection, decoding and storing readings (1.3.3); heartbeat (1.2.8).
- Device settings and alert editing (1.2.9), reorder (1.2.10), the Remove device screen (1.2.11; it can reuse `DeviceService.removeDevice`).
- Dedicated screens for Bluetooth off, nothing found or connect failed: one inline error with Try again.
- The real cloud call (Phase 2).

## Phase behaviour

| isCloud | Behaviour |
| --- | --- |
| false (Phase 1) | Saved on the phone with the config default alerts. No network calls. No device key card; checklist "Connected to device", "Saved on this phone"; badge "Default settings". |
| true (Phase 2) | Same save, then `CloudDeviceRegistration` (empty hook, returns nothing). Device key card shown ("Waiting for the cloud" until the hook returns a key); the 4 cloud checklist rows; "Suggested by cloud AI" when the cloud sends alerts. |

## Open items

- The device dashboard route is a placeholder until its task.
- Phase 2: the cloud API for registration.
- A denied Bluetooth permission shows a message only; no button that opens the phone's Settings.
