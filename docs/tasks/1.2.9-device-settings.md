# Task 1.2.9 – Device settings screen

## Goal

From a device, the user opens Device settings: they can rename it, see its type, connection, address, firmware, battery and last heartbeat, turn each alert limit on or off, and remove it from the phone after confirming.

## Requirements covered

- §8.1 Rename; type, connection, device ID (MAC or IP), signal, firmware, battery.
- §8.2 Heartbeat interval, last heartbeat, offline rule, device status (partly; see Open items).
- §8.3 Sampling interval 1 s / 5 s / 30 s / 1 min (shown, not changeable yet; see Open items).
- §8.4 Turn each alert limit on or off.
- §8.5 Remove device: confirm, then delete it and its alert limits from the phone; Phase 2 also tells the cloud.
- Mockup screens 25 (Device settings) and 26 (Remove device sheet); mockup HTML for the rows and labels.

## Scope

**In scope**

- `DeviceService.watchDevice` (one device with its alert limits; null for another user's device) and `setAlertEnabled`.
- `DeviceSettingsScreen` at `/device/:id/settings`, full screen without the tab bar; the round Device settings button in the device page header (`LiveDeviceScreen`, and its placeholder for profiles without a `packet` block). Reached from Home: device card → device page → Device settings.
- Rename on keyboard Done, on leaving the field, or on Back; the same 1–40 character rule as Add device.
- The Remove device bottom sheet; its text uses the config's `history.daysOnPhone`.

**Out of scope**

- The device dashboard (1.3.4). Home device cards exist since 1.3.3; reorder (1.2.10) and swipe to delete (1.2.11) are their own tasks.
- Heartbeat config and status (1.2.8), live signal strength (needs the live connection state).
- Changing alert limits (requirement §8.4 is on/off only).
- Swipe-to-delete on Home (1.2.11).

## Phase behaviour

| isCloud | Behaviour |
| --- | --- |
| false (Phase 1) | Everything is read from and saved to the phone. No network calls. |
| true (Phase 2) | Same screen. Remove also calls `DeviceRegistration.unregister` (the existing empty hook). |

## Open items

- Heartbeat interval, offline rule and device status show "—" until the profile has a heartbeat config (1.2.8).
- Signal (RSSI) shows "—" until the live connection state is available.
- Sampling interval: shown but disabled ("Set by the device for now."); nothing stores it and no profile has a "set interval" command (requirements open question on whether a device accepts a new interval).
- Last heartbeat shows the device row's last-data time, which the reading pipeline (1.3.3) now updates while the device is connected.
- Removing the device that is currently connected: `ActiveDevice` notices it is gone and disconnects it.
- The name field starts filled with the current name (the mockup shows it as a hint) so it can be edited.

## Acceptance criteria

- [x] Every row of mockup screen 25 is shown; MAC address for BLE, IP address for Wi‑Fi; "—" where the phone has no value.
- [x] Rename saves a valid changed name and shows the rule's message for an invalid one; nothing is saved twice.
- [x] Each alert switch saves on/off; the limit stays.
- [x] Remove asks in a bottom sheet; Cancel keeps the device; Remove deletes it, goes Home and shows "Device removed"; a failure stays with a message.
- [x] Another user's device or an unknown id shows "This device is no longer on this phone."
- [x] Unit and widget tests (mocktail, table-driven where there are cases), including dark mode and a small phone at double text size; `flutter analyze` and `flutter test` are clean.
- [x] Every button has a Semantics label; each alert switch is read with its limit; the disabled sampling control is announced as disabled.
- [ ] Manual check on a phone with a real device: Home card → device page → Device settings; rename, toggle an alert, remove.
