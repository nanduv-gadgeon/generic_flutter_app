# Task 1.2.6 – Wi‑Fi provisioning (BLE / SoftAP) and local Wi‑Fi transport (mDNS, WebSocket / HTTP)

## Goal

The app can give a Wi‑Fi device of a configured type the home network's name and password (over BLE or the device's own hotspot), find it again on the local network by mDNS, and receive its data and send it commands over WebSocket or HTTP poll, reconnecting by itself. Add device (1.2.7) builds the screens on it.

## Requirements covered

- 4.2 Add a device: Wi‑Fi (send network name and password to the device); options come from the device type in the config file.
- Config file, "Connection" row: Wi‑Fi setup method and instructions.
- Architecture, "Device communication": Wi‑Fi setup, Wi‑Fi data, reconnect with backoff 2, 5, 15, 60 s.
- Security design, "Devices": Wi‑Fi password protected in transit, never logged.
- Architecture, "Devices" row: `dio`, `web_socket_channel`, `multicast_dns`.

## Scope

**In scope**

- Profile `wifi` block (optional): schema, model, checks; `isConnectable` for Wi‑Fi.
- The generic Wi‑Fi setup contract in `docs/protocols/README.md`.
- `isLanHost` guard: Wi‑Fi code only talks to local addresses.
- `WifiProvisioner` (BLE and SoftAP), `WifiDeviceFinder` (mDNS), `WifiDeviceLink` (WebSocket / HTTP poll).
- BLE scan for devices in Wi‑Fi setup mode.
- Android and iOS local-network permissions.

**Out of scope**

- Add device screens, credential entry and SoftAP instructions: 1.2.7.
- Link → decoder → database wiring: 1.3.3. Heartbeat: 1.2.8.
- Joining the device hotspot from the app (the user joins it in phone Settings).
- Storing Wi‑Fi credentials on the phone (never done).
- The env sensor's real `wifi` block: when its protocol document arrives.

## Open items

- `env_sensor_v1` has no Wi‑Fi protocol document, so no `wifi` block; it cannot connect over Wi‑Fi yet.
- Credentials are protected by the link only (bonded BLE, WPA2 device hotspot). App-level encryption waits for a device protocol that defines it.
- iOS `NSBonjourServices` must list each customer's `mdnsService` values; it lists only the test service now.
- Plain `http://` / `ws://` to local devices needs no platform exception (Dart sockets); confirm on real phones in 1.2.16.
- The iOS local-network permission prompt appears on the first mDNS lookup; 1.2.7 should explain it before then.

## Acceptance criteria

- [x] Hosts outside the local network are refused before any connection.
- [x] BLE setup writes the credentials, waits for the reply with a timeout and always disconnects.
- [x] SoftAP setup posts the credentials to the configured address and explains when the device is unreachable.
- [x] The password never appears in logs, exceptions or `toString()`.
- [x] The Wi‑Fi link streams packets (WebSocket or HTTP poll), sends commands and reconnects with 2, 5, 15, then 60 s.
- [x] Unit tests added (mocktail, table-driven where there are cases); `flutter analyze` and `flutter test` are clean.
- [ ] Manual check with a real Wi‑Fi device (1.2.16).
