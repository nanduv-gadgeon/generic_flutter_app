# Task 1.3.4 + 1.3.5 – Live dashboard built from the device profile

## Goal

Every device type's Live dashboard (mockup screens 13–21) is built by one screen from its profile, so a new device type needs config, not a new screen.

## Requirements covered

- §5 Live dashboard: status strip, Live / History, main reading with gauge, normal range, status and 30-minute trend, tiles with range bar or goal
- §6 Config: dashboard main reading, tile order, normal range or goal per reading
- Device list from mockup v2 (Add device step 1, screen 10)

## Scope

**In scope**

- The 9 device types of mockup v2
- View types (registry): `gauge`, `tiles` (range / goal / plain / no-signal tiles), `spotValue`, `note`, `readingList`, `waveform`, built from 5 shared parts (`DashCard`, `StatusPill`, `ScaleBar`, `TraceChart`, `ArcGauge`)
- Shell: header, status strip (`heartbeat`, `state`, `lastReading`, `streamRate`, `channels`), Live / History tabs
- Device events (START / STOP / ERROR) stored (schema v6) and summed for today: Run time, Sessions, Errors, State
- Dashboard text in `app_en.arb`

**Out of scope**

- Sync now / action buttons, offline banner + Reconnect, PPG Enabled-channels toggles (1.3.6)
- PPG Motion (IMU) graph
- History tab content (Module 4)
- Real protocols for the thermometer, ECG monitor and hub
