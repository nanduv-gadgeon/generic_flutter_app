# Task 1.4.6 – Export CSV / PDF and share sheet

## Goal

From History the user exports the picked device's last days as a **CSV file** or a **PDF report**, and the phone's share sheet opens with it. Export works in local mode only: with `isCloud` true the Export button is hidden.

## Requirements covered

- 6.6 Export: the user picks CSV file or PDF report for the chosen device's last 7 days. Days with missing data are marked, a spinner shows while the file is made, then the share sheet opens.
- Privacy: files are made only when the user asks, shared through the share sheet, and deleted afterwards (architecture.md, Security).
- Accessibility: every button, radio and spinner has a Semantics label; text scales.

Reference: screen 33 (`docs/screens/33_export_sheet.png`).

## Scope

**In scope**

- **Export button**: an outlined pill with a download icon at the top right of History (icon only with large text).
  - It shows only when `exportAvailable` is true: `isCloud` false and `features.export` true. It's worked out in `core/di`; History never checks isCloud.
  - With the cloud on, nothing is shown and nothing in the cloud code changes.
- **Export sheet**:
  - "Export history" and "{device} · last 7 days (20–26 Oct). All readings, with days that have missing data marked."
  - CSV file / PDF report (CSV is picked first).
  - **Export and share**, with a labelled spinner while the file is made, and **Cancel**.
  - The sheet closes once the file is shared. On a failure it says "Couldn't export the file. Try again." and stays open.
- **CSV**, with every stored reading of the device's profile over the days History shows:
  - The columns are Date (yyyy-mm-dd), Time (local hh:mm:ss), Reading, Value, Unit and Day status.
  - Rows are in time order. The day's status is Complete or Partial, from the readings' own hours, as on the day strip. A day without readings gets one "No data" row.
  - Values are plain numbers with the reading's decimals and no thousands separators. Sleep is written in hours ("h").
  - The file is UTF-8 with a byte order mark, so spreadsheets show "°C" and "SpO₂". Text fields starting with `= + - @` get a leading apostrophe (OWASP CSV injection).
  - It's built on another isolate.
- **PDF**, using the config's font (`theme.font`) and colours. It contains:
  - the title, the device and days, and when it was made;
  - per reading shown on History, its 7-day bars, as on the summary tab (1.4.5);
  - a table of Date / Min / Average / Max / Status, where a missing day shows "–" and **Missing**.
- **File handling**: the file is written to the phone's temporary folder as `history-<yyyymmdd>.csv` or `.pdf`, shared, then deleted, even when sharing fails. There are no network calls.

**Out of scope**

- Export in cloud mode (hidden, decision 2026-11-16).
- Choosing columns or formats from the config (requirement table, "Export: formats offered, columns"). All formats are offered while `features.export` is on.

- [x] PDF: charts and a daily table per reading; missing days marked "Missing".
- [x] A labelled spinner while the file is made; the share sheet opens; the file is deleted afterwards (also on failure).
- [x] Every new button, radio and spinner has a Semantics label; fits a 320 × 568 phone at 2× text.
