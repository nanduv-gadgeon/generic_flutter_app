# Task 1.4.5 – 7-day summary chart per reading type

## Goal

The **7-day summary** tab of History shows one reading of the picked device over the days kept on the phone. It has one bar per day, the lowest, average and highest of the daily values, and a list of the days with their status. Each reading's daily value suits its type: the daily average for heart rate, the daily total for steps.

## Requirements covered

- 6.2 Pick a reading (picking a device is done in 1.4.4).
- 6.5 A 7-day summary chart for the chosen reading, suited to its type (e.g. daily totals for steps, daily average for heart rate).
- Accessibility: colour is never the only signal; every chip, bar and spinner has a Semantics label; text scales.

Reference: screen 24 (`docs/screens/24_history_summary.png`), mockup `hist.bySummary`.

## Scope

**In scope**

- **Reading chips** under By day / 7-day summary. There is one chip per reading in Live dashboard order, using the same readings as By day's cards (`historyReadings`).
  - The picked chip is tinted.
  - The first reading is picked until the user picks another, or when the picked one isn't on the next device.
- **Chart card**:
  - **Title:** "Heart rate · daily average", or "Steps · daily total" for a reading with a goal.
  - **Big number:** the average of the days' values ("72 bpm avg").
  - **Bars:** one per day, oldest first and today last ("Today").
    - The value is above the bar and the weekday under it, from `intl`.
    - Today's bar uses the primary colour and the others `barSoft`. A value outside the normal range is drawn in the warning colour.
    - A day without data is a dashed "No data" box in the danger colour.
    - A bar starts at 0 for totals. Otherwise it starts at 0.8 × the spread below the lowest value (10 % of it when every day is the same), so small differences show. It doesn't go below 0 unless a value does.
- **Min / Average / Max** tiles of the days' values.
- **Day list**, newest first, e.g. "Today · Mon 26 Oct · 72 bpm · Normal". The status is decided in this order:
  1. **Missing** (no data);
  2. **High** or **Low** (outside the normal range);
  3. **Partial** (this reading has gaps; today counts only the hours begun so far);
  4. **Normal**.
- **Daily value per reading**: a reading with a goal (steps, sleep, active time) counts up through the day, so its value is the day's total, which is its highest (1.4.3). Every other reading uses the day's average.
- **History unit**: a new optional `historyUnit` per reading in the config, used where the Live unit doesn't suit a daily value ("steps" instead of "today", "min" instead of "min today"). Hours written as "7h 12m" show no unit.
- **States**:
  - a labelled spinner while loading;
  - "Couldn't load the summary." on an error;
  - "No readings in the last 7 days" when there is nothing (the chips stay);
  - "This device has no readings to summarise." when the profile has none.

**Out of scope**

- The "activity" day rule ("Not used" instead of "No data" for therapy and thermometer days) and readings worked out from events (Run time, Sessions, Errors). These need agreeing with QA, as in 1.4.4.
- Export (1.4.6).

## Data sources

It runs no new queries and makes no schema change. Everything comes from 1.4.4's `historySummaries(deviceId)`:
- **Finished days:** the stored daily summaries (1.4.3).
- **Today:** worked out every minute.
- **Yesterday:** caught up after midnight.
