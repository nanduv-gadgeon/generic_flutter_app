# Task 1.1.4 – Config file loader, schema check, theme tokens, isCloud wiring

## Goal

The app reads the customer config file on the splash screen and checks it against a JSON Schema. It builds its theme from the config. It also picks its Phase 1 or Phase 2 services from `isCloud`, in one place. This sets the pattern that later tasks follow.

## Requirements covered

- 1.1–1.4 App start: config read on the splash screen, `isCloud` checked, brand ready for login, and a backend check with retry in Phase 2
- Config file table: cloud switch, brand, theme, typography and features
- Quality: config schema-checked in CI; with `isCloud: false`, no network calls

## Scope

**In scope**

- Config model for `isCloud`, `brand`, `theme`, `features`, `history`, `cloud` and `deviceTypes`
- `assets/config/app_config.schema.json`, checked when the app starts and in `flutter test`
- Theme built from the config, with `AppTokens` (status colours, neutrals, radii) taken from the mockup
- `Uploader` and `BackendHealth` interfaces, Phase 1 implementations and empty Phase 2 hooks, wired in `core/di`
- The splash screen waits for the config and the backend check, and shows an error or a Retry button

**Out of scope**

- Device profile model and registry (1.2.3)
- AuthService and login (1.1.6)
- Splash logo and design (1.1.7)
- Real cloud calls (Phase 2)

## Interfaces / files expected

| File | Layer | Purpose |
| --- | --- | --- |
| `lib/core/config/app_config.dart`, `config_sections.dart` | core | Freezed config models |
| `lib/core/config/config_loader.dart` | core | Load the config, check it against the schema, raise `ConfigException` |
| `lib/core/theme/app_tokens.dart`, `app_theme.dart` | core | `ThemeExtension` tokens and `buildTheme` |
| `lib/domain/services/uploader.dart`, `backend_health.dart` | domain | Service interfaces |
| `lib/data/upload/*`, `lib/data/cloud/*` | data | `NoUploader`, `CloudUploader`, `LocalBackendHealth`, `CloudBackendHealth` |
| `lib/core/di/services.dart` | core | The only `isCloud` branch |

## Phase behaviour

| isCloud | Behaviour |
| --- | --- |
| false (Phase 1) | `NoUploader` and `LocalBackendHealth`: no I/O and zero network calls. The `cloud` block is optional. |
| true (Phase 2) | `CloudUploader` and `CloudBackendHealth`: empty hooks marked `// TODO(phase2)`. The `cloud` block is required and its `baseUrl` must be `https://`. |

## Acceptance criteria

- [ ] An invalid config (bad colour, unknown key, `http://` URL, a missing block) is rejected with its JSON path
- [ ] Every `assets/config/*/app_config.json` passes the schema in `flutter test`
- [ ] The theme's primary colour, radius, font and mode come from the config, with light and dark tokens
- [ ] `isCloud` is branched only in `lib/core/di/`
- [ ] The splash screen goes to `/login`, shows an error if the config is invalid, and shows Retry if the backend can't be reached
- [ ] Unit tests added (mocktail); `flutter analyze` and `flutter test` are clean
- [ ] Every new button and spinner has a Semantics label
