# Task 1.2.10 – Reorder devices

## Goal

On My devices, users can change the order of their device cards by dragging a ≡ handle. The new order is saved and kept.

## Requirements covered

- 3.6 **Reorder**: press and drag the ≡ handle to move a device, in the usual phone style. Arrow keys also work. The order is kept.
- Accessibility: reorder also works with arrow keys, every button has a screen reader label, and text scales with the phone settings.

## Scope

**In scope**

- A **Reorder** button to the right of the "My devices" heading, shown only when there are two or more devices. It switches home to reorder mode (`docs/screens/09_home_reorder.png`):
  - a hint line;
  - one compact row per device (icon, name, type) with a ≡ handle;
  - **Done** in place of Reorder.
- Moving a device:
  - press and drag the handle;
  - or focus the handle and press the Up or Down arrow key;
  - screen readers also get the list's own move actions.
- **Saving on every drop.** The list shows the new order at once and saves it through `DeviceService.reorder`. It isn't held until Done.
- In reorder mode, tapping a row doesn't open the device. "Add a device" stays below the list.
- If fewer than two devices remain, reorder mode ends.
- **Debug builds only (`kDebugMode`):** a long-press on the "My devices" heading adds 4 dummy devices, using the config's device types and made-up `AA:BB:CC:DD:00:0n` addresses. A second long-press removes them. A snackbar says what changed. There's no visible button, and release builds don't have it.

**Out of scope**

- Swipe to delete (1.2.11).
- Changing the order of reading tiles on the dashboard.
- Syncing the order to the cloud (Phase 2).

| File | Layer | Purpose |
| --- | --- | --- |
| `lib/domain/devices/device_order.dart` | domain | `moveItem`: pure list move used by drag and arrow keys |
| `lib/domain/services/device_service.dart` | domain | `reorder(userId, orderedIds)`; other users' ids are ignored |
| `lib/data/devices/local_device_service.dart` | data | `reorder` calls the existing `DevicesDao.reorder` (one transaction setting `sortOrder`) |
| `lib/application/devices_provider.dart` | application | `saveDeviceOrderProvider`: saves for the logged-in user |
| `lib/application/debug_dummy_devices.dart` | application | `DummyDevices.toggle`: debug-only dummy devices |
| `lib/presentation/devices/home_screen.dart` | presentation | Reorder mode state; swaps the cards for the reorder list |
| `lib/presentation/devices/home_reorder_list.dart` | presentation | `HomeReorderList`: rows, handles, arrow keys, optimistic order |
| `lib/presentation/devices/home_list_parts.dart` | presentation | `MyDevicesHeading` (Reorder / Done, debug long-press), `AddDeviceTile`, `EmptyDevicesCard`, moved out of home to stay under 300 lines |
| `lib/presentation/strings/devices_strings.dart` | presentation | Reorder, hint, handle and row labels; dummy-device messages |

## Phase behaviour

| isCloud | Behaviour |
| --- | --- |
| false (Phase 1) | The order is saved in the local DB only. No network calls. |
| true (Phase 2) | Same. Syncing the order is not planned. |

## Acceptance criteria

- [x] Reorder is shown only with two or more devices.
- [x] Dragging a handle moves the device, and the new order is saved on the drop.
- [x] Up and Down arrows on a focused handle move the device. Up on the first device does nothing.
- [x] The saved order comes back from `watchDevices`. Other users' devices are not changed.
- [x] Tapping a row in reorder mode doesn't open the device. Done returns to the cards.
- [x] Fits a 320 × 640 phone at 2× text size.
- [x] Dummy devices exist only in debug builds.
- [x] Unit tests added (mocktail); `flutter analyze` and `flutter test` are clean.
- [x] Every new button has a Semantics label. Order is shown by position and handles, not colour.
